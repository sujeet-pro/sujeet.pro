**Cutover and ownership**

- **Shadow first.** The function computes its answer while the origin still serves, and logs every mismatch. Flip only when the mismatch count is zero.
- **SEO sign-off.** Status codes and targets must not change at cutover. A 302 that turns into a 301 is a behaviour change for search engines and for browser caches.
- **Ownership.** The platform team owns the function and the publish path; marketing owns the rules. Write that split down before the first incident, not during it.

**Where can a ≈12 MB filter live?** (10M slugs, 1% false-positive rate)

- KVS value, 1 KB: no.
- Whole KeyValueStore, 5 MB: no (2.4× over).
- CloudFront Function, 10 KB code / 2 MB memory: no.
- Lambda@Edge, 50 MB package: yes, at $0.60 vs $0.10 per 1M requests, plus duration, and no KVS access.
- Fargate task memory, in-process: yes. Chosen.

```ts
import { DynamoDBClient, GetItemCommand } from '@aws-sdk/client-dynamodb';

// Rebuilt from the table on a schedule; writes are added live.
interface BloomFilter {
  ready: boolean;
  mightContain(slug: string): boolean;
}

const ddb = new DynamoDBClient({});

// Regional service: the Bloom filter guards DynamoDB, not the edge.
// 10M slugs at a 1% false-positive rate ≈ 12 MB (9.585 bits/key, k = 7).
export async function resolve(
  bloom: BloomFilter,
  slug: string,
): Promise<string | null> {
  // No false negatives: "absent" is final; the edge caches the 404.
  // Fail open while the filter (re)loads.
  if (bloom.ready && !bloom.mightContain(slug)) return null;

  // "Maybe": ~1% of misses still land here (1% false-positive rate).
  const { Item } = await ddb.send(
    new GetItemCommand({
      TableName: 'redirects',
      Key: { slug: { S: slug } },
      ConsistentRead: false,
    }),
  );
  return Item?.target?.S ?? null;
}
```

**Cutover runbook**

- **Shadow-replay.** Replay a day of logged paths per tenant through the old and new matchers; block cutover on any unexplained diff. A compiler that rejects overlapping rules at publish time catches conflicts before replay has to.
- **DNS cutover.** Lower record TTLs ahead of the move, shift traffic in weighted steps, and keep the old path serving until the old TTL has fully drained.
- **SEO sign-off.** Each tenant domain signs off on status codes and canonical targets before its switch.
- **Ownership.** Each tenant names an owner for its rules. The platform team owns precedence semantics and the compiler. Cheaper tooling doesn't shorten these conversations.
